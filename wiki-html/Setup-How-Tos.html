🔐 AWS SSM Parameter Bootstrap

All secrets (API keys, Plaid credentials, encryption keys) live in AWS SSM Parameter Store under the /monet/{stage}/ prefix. Instead of putting them manually one-by-one, use the bootstrap script at raw/croe/scripts/ssm-bootstrap.sh.

Prerequisites

  • AWS CLI v2 installed (aws --version)
  • Named AWS profile with ssm:PutParameter and kms:GenerateDataKey permissions
  • openssl available for auto-generating secrets

Run the script

# From the repo root
cd raw/croe

# Dev stage
./scripts/ssm-bootstrap.sh --stage dev --profile dev

# Prod stage
./scripts/ssm-bootstrap.sh --stage prod --profile dev

The script is interactive — it prompts for each value, shows you exactly where to find it, and auto-generates anything you leave blank (encryption key, JWT secrets, origin secret).

Flags

FlagDefaultDescription
--stagerequireddev or prod
--profiledevAWS named profile
--regionus-east-1AWS region
--overwriteoffPass to update existing params; omit to skip them safely

Verify after bootstrap

aws ssm get-parameters-by-path \
  --profile dev --region us-east-1 \
  --path "/monet/dev" --recursive \
  --query "Parameters[*].Name" --output table

⚠️ Security reminders
Never reuse plaid-encryption-key between stages — rotating it requires re-encrypting every stored Plaid access token in DynamoDB. Restrict google-places-api-key to your API Gateway origin in GCP Console.

Next steps after bootstrap

  1. Deploy: npx serverless deploy --stage dev --profile dev
  2. Copy the CloudFrontDomain stack output into Secrets.xcconfig → CLOUDFRONT_URL
  3. If you auto-generated origin-secret, update the CloudFront origin custom header value to match it

🗄️ Local DynamoDB Setup

The backend auto-detects local vs. Lambda by checking for LAMBDA_TASK_ROOT. Locally it points to http://127.0.0.1:8000 with dummy credentials. You need a local DynamoDB running before starting the dev server.

Option A — DynamoDB Local JAR (recommended)

Download DynamoDB Local from AWS and run it from a separate terminal:

# In a separate terminal — keep this running
cd ~/Desktop/dynamodb_local_latest
java -Djava.library.path=./DynamoDBLocal_lib \
     -jar DynamoDBLocal.jar \
     -sharedDb \
     -dbPath ./dynamodb_data

💡 Tip: The -sharedDb flag makes all tables visible across credentials/regions. The -dbPath flag persists data between restarts so you don't need to re-seed after each restart.

Option B — Docker

docker run --rm -p 8000:8000 amazon/dynamodb-local

Note: Docker mode is ephemeral — tables reset on container exit.

Initialize tables

Once the database is running, create all five tables in a single command:

cd raw/croe
npm run init-db

This runs src/init-db.ts which creates the following tables (skipping any that already exist):

TableKeysGSIs / LSIs
MonetUsers PK: id —
MonetOverrides PK: userId / SK: merchantId GSI: MerchantIdIndex
MonetTransactions PK: userId / SK: transactionId LSI: DateIndex; GSI: MerchantNameIndex, CategoryIndex
MonetInsightsCache PK: userId / SK: cacheKey —
MonetBrandCache PK: brandName —

ℹ️ Health check: If the dev server starts and DynamoDB is unreachable, local-db-health-check.ts catches the connection error and prints actionable fix instructions before exiting, so you'll know exactly what's wrong.

⚡ Running the Dev Server

The backend is a Node 20 / Express app bundled with esbuild for Lambda, but it runs as a plain HTTP server locally on port 3000.

1. Install dependencies

cd raw/croe
npm install

2. Configure environment variables

Copy .env.example to .env and fill in your values:

cp .env.example .env
VariableRequired locallyNotes
PORTNoDefaults to 3000
PLAID_CLIENT_IDYes (for Plaid features)From Plaid Dashboard
PLAID_SECRETYes (for Plaid features)Sandbox secret for dev
PLAID_ENVYessandbox for dev
PLAID_ENCRYPTION_KEYYesAny 32-character string locally
GOOGLE_CLIENT_IDNo (guest JWT works without it)Only needed for Google Sign-In verification
APPLE_CLIENT_IDNoOnly needed for Apple Sign-In verification
MONET_ORIGIN_SECRETNoOnly enforced in deployed envs

3. Start local DynamoDB

See Local DynamoDB Setup above. Run in a separate terminal window.

4. Initialize tables (first run only)

npm run init-db

5. Start the dev server

npm run dev

This runs tsx watch src/index.ts with hot-reload. The server listens on http://localhost:3000. The predev hook automatically kills any existing process on port 3000 before starting.

Verify the server is running

curl http://localhost:3000/health

Expected response: {"status":"ok"}

💡 Dev API key: For testing protected endpoints locally without signing in, set MONET_DEV_API_KEY in .env and pass it as the X-Dev-Api-Key header in Postman. This bypass is blocked entirely in the deployed Lambda.

☁️ One-time AWS Setup Notes

Enable Bedrock Model Invocation Logging

This is an account/region-wide setting that can't be managed via CloudFormation. Run once after your first Serverless deployment:

aws bedrock put-model-invocation-logging-configuration \
    --logging-config '{
        "textDataDeliveryEnabled": true,
        "imageDataDeliveryEnabled": false,
        "embeddingDataDeliveryEnabled": false,
        "videoDataDeliveryEnabled": false,
        "audioDataDeliveryEnabled": false,
        "cloudWatchConfig": {
            "logGroupName": "/aws/bedrock/model-invocation-logs-dev",
            "roleArn": "arn:aws:iam::050836710032:role/BedrockLoggingRole-dev"
        }
    }' \
    --profile dev \
    --region us-east-1
