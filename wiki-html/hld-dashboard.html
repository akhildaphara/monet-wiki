Monet Technical Reference

A comprehensive guide to the Monet backend architecture, data flows, and REST API registry.

System Architecture Map

The Monet platform leverages a serverless Node.js/Express Lambda architecture deployed via AWS API Gateway. It serves both the Swift iOS application and the Next.js Web client, utilizing DynamoDB for high-speed state management and integrating tightly with Plaid for transaction intelligence.

Key Data Flows

1. Authentication & Bootstrapping

The initial boot and synchronization flow, bringing the client up to date with the latest user profile, card wallet, and custom overrides via a single unified request.

sequenceDiagram participant Client as 📱 Client participant Auth as 🔑 Google Auth participant API as ⚡ Backend (/sync) participant DB as 🗄️ DynamoDB Client->>Auth: Authenticate Auth-->>Client: ID Token Client->>API: POST /v1/auth/sync (Token) API->>API: Verify Token Integrity API->>DB: Fetch User (MonetUsers) API->>DB: Fetch Overrides (MonetOverrides) DB-->>API: Data Payload API-->>Client: { user, overrides, cards }

2. Recommendation Engine

The core path for determining the highest rewarding card for a specific merchant or broad category.

sequenceDiagram participant Client as 📱 Client participant API as ⚡ Backend participant Places as 🗺️ Google Places participant DB as 🗄️ DynamoDB Client->>API: POST /v1/recommend {name, category} opt Name provided without explicit category API->>Places: Query Places API Places-->>API: Merchant Category Resolution end API->>DB: Get User Rewards & Overrides API->>API: Evaluate Deck & Calculate Max Reward API-->>Client: { bestCard, allRates, marketBest }

3. Plaid Insights Processing

A heavy computational background sync for downloading transactions, categorizing them, and generating historical spending insights and missed rewards.

sequenceDiagram participant Client as 📱 Client participant API as ⚡ Backend (/insights/sync) participant Plaid as 🏦 Plaid participant DB as 🗄️ DynamoDB Client->>API: POST insights/sync API->>Plaid: Fetch recent transactions Plaid-->>API: Sync Updates API->>DB: Persist new transactions loop For each transaction API->>API: Calculate actual earnings API->>API: Calculate optimal (missed) earnings API->>API: Aggregate by category end API-->>Client: { summary, categories, transactions }

User Profile & Overrides

POST /v1/user/cards Updates custom wallet configuration. ▼

Modifies nicknames, last 4 digits, cycle dates, or reward multipliers for existing cards in the user's wallet.

Auth: Required
Request Body
{
  "cards": {
    "card_id_1": {
      "nickname": "string?",
      "last4": "string?",
      "cycleStartDate": "string?",
      "customRewards": { "Dining": 3 }
    }
  }
}
Response (200 OK)
{
  "success": "boolean",
  "user": "SanitizedUser",
  "cards": ["CardListItem"]
}
POST /v1/user/overrides Creates a merchant category override. ▼

Forces a specific merchant to always resolve to a chosen category for the authenticated user.

Auth: Required
Request Body
{
  "merchantName": "string",
  "category": "string"
}
Response (200 OK)
{
  "success": "boolean",
  "override": "OverrideRecord?",
  "error": "string?"
}
DELETE /v1/user/overrides/:merchantId Removes a merchant override. ▼
Auth: Required
Response (200 OK)
{
  "success": "boolean",
  "error": "string?"
}
