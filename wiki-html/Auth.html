Security

Authentication & Security

Every request flows through CloudFront → Lambda authorizer → Express. Three token types are accepted (Google, Apple, Guest JWT) plus a dev key. Guests get a real short-lived JWT so all protected routes work without signing in.

Architecture Overview

Token Types

The Lambda authorizer checks credentials in priority order. First match wins.

Guest JWT Priority 2

Short-lived token from POST /v1/auth/guest. Gives unauthenticated users access to the full app without signing in.

alg HS256
iss monet-guest
sub guest-<uuid>
exp 1 hour
key SSM /monet/dev/guest-jwt-secret

Stored in-memory only. Auto-refreshed via onTokenExpired.

Google JWT Priority 3

ID token from Google Sign-In. Verified against Google's public JWKS. sub becomes the permanent userId.

iss accounts.google.com
aud monet Google client ID
exp ~1 hour
key Google public JWKS

Silently refreshed via GIDSignIn.refreshTokensIfNeeded().

Apple JWT Priority 4

Identity token from Sign in with Apple. Apple only provides name/email on first auth — cached in UserDefaults.

iss https://appleid.apple.com
sub stable Apple user ID
key Apple public JWKS

Disabled Requires paid Apple Developer account.

X-Dev-Api-Key Priority 1 — dev only

Shared secret for Postman / local dev. Bypasses token verification. Rejected when NODE_ENV === "production".

header X-Dev-Api-Key: <key>
userId "dev-bypass"
key SSM /monet/dev/dev-api-key
env development / IS_LOCAL only

Postman: add X-Dev-Api-Key header, skip Authorization.

Route Auth Matrix

Method Path Authorizer Reason
GET /health None Infrastructure health check
POST /v1/plaid/webhook None Plaid signs its own payload; verified in handler
POST /v1/auth/guest None Bootstrap endpoint — requires valid X-Monet-App-Key header to prevent non-app client token minting
GET /v1/cards monetAuthorizer Curated master catalog; accessible to authenticated users (including guests) to protect proprietary reward metadata
ANY /{proxy+} monetAuthorizer /recommend, /auth/sync, /user/*, /plaid/* & all others
Card Catalog Security: The /v1/cards route requires authentication (valid Guest or Registered JWT) and is excluded from edge-caching to prevent public scraping of Monet's highly curated credit card rewards taxonomy.

Origin Secret

The Lambda authorizer validates that every inbound request came via CloudFront, not directly to the raw execute-api URL. CloudFront adds the secret as a custom origin header; the authorizer rejects anything without it.

CloudFront → Origin

X-Origin-Secret: <SSM value>

Added automatically to every origin request by the CloudFront distribution's OriginCustomHeaders.

Lambda Authorizer check

// first check, before any token logic
if (header !== env.MONET_ORIGIN_SECRET)
  return { isAuthorized: false }

Skipped when IS_LOCAL=true.

iOS Auth Flow

Guest mode — new user

The key constraint: isGuest = true is set only after the token is in hand, so RootTabView never renders without a valid authToken.

Steps 2–3 happen inside the async await continueAsGuest() call. The UI doesn't advance to step 4 until the token is ready.

Guest mode — app restart (restore)

  1. AuthService.init() detects isGuestSession=true in UserDefaults.
  2. Sets isCheckingAuth = true — splash screen stays visible.
  3. Background task calls POST /auth/guest to mint a fresh token (the previous one expired after 1h).
  4. On success: APIClient.authToken = newToken → isGuest = true → isCheckingAuth = false.
  5. RootTabView renders, .task calls loadGuestCatalog() — token is already in place.

Token refresh (all session types)

Session onTokenExpired action Outcome
Guest POST /auth/guest New 1h guest JWT, retry
Google refreshTokensIfNeeded() New Google ID token, retry
Apple Cannot refresh silently onSessionExpired → signOut()

AuthService State Machine

Sign Out & Data Cleanup

AuthService.signOut() is shared by "Sign Out" (signed-in) and "Start Over" (guest). It fully wipes the session and all local data.

What gets cleared

  • — APIClient.authToken (in-memory)
  • — All SwiftData models (cards, user, overrides)
  • — UserDefaults: provider, appleToken, appleName, appleEmail, isGuestSession, lastSignedInUserId
  • — GIDSignIn session

Trigger chain

  • signOut() calls APIClient.onAccountSwitch?() → DataStore.clearAllData()
  • applyAccountSwitchIfNeeded() wipes data when a different user signs in
  • onSessionExpired fires on persistent 401 → calls signOut()

Insights — Sign-in Wall

The Insights tab requires a real user account (Plaid items are scoped to a stable userId) and a connected bank. Guests see a wall instead of an empty state.

Guest sees

  • InsightsTapestryView decoration
  • "Sign in to unlock Insights"
  • Primary "Sign In" button → presents SignInView sheet

After signing in

  • isSignedIn flips true, sheet auto-dismisses
  • Wall disappears; Connect Bank flow activates
  • Backend syncs via POST /auth/sync
Why Insights requires sign-in: Plaid creates a persistent Item linked to a userId in DynamoDB. Guest IDs (guest-<uuid>) are ephemeral and regenerated each session — any Plaid Item linked to them is unrecoverable.

SSM Parameters

Secrets live in AWS SSM (SecureString) and are injected as Lambda environment variables at deploy time.

Parameter Env var Used by Purpose
/monet/dev/guest-jwt-secret MONET_GUEST_JWT_SECRET authorizer + api λ Signs and verifies guest JWTs (HS256)
/monet/dev/dev-api-key MONET_DEV_API_KEY authorizer λ Postman / dev bypass (dev only)
/monet/dev/origin-secret MONET_ORIGIN_SECRET authorizer λ + CloudFront Blocks direct API Gateway access

Local Dev vs Production

iOS DEBUG build

Hits http://<LOCAL_API_HOST>/v1 set in Secrets.xcconfig. No CloudFront or Lambda authorizer. auth.ts falls back to direct token verification.

iOS RELEASE build

Hits https://d2fbowggfpw2nf.cloudfront.net/v1 from CLOUDFRONT_URL in Secrets.xcconfig → Info.plist. Full stack active.

Backend local (npm run dev)

IS_LOCAL=true skips X-Origin-Secret check. No req.apiGateway context; auth.ts verifies tokens directly.

Postman (deployed)

Base: https://d2fbowggfpw2nf.cloudfront.net. Add X-Dev-Api-Key: 8d87090a... header. Protected routes work without an Authorization header.

Future — App Attest

Deferred until paid Apple Developer enrollment. When active, POST /v1/auth/guest will require an App Attest assertion before minting a guest JWT, cryptographically proving the request came from a genuine Monet binary. The X-Dev-Api-Key bypass stays for Postman/dev only.
