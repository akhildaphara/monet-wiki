Product surfaces

  • iOS: SwiftUI/SwiftData app with Search, Insights, Calculator, Wallet, and Settings tabs; guest, Google, Apple, and native email/password sessions; Plaid Link; cached/offline recommendations; custom rewards; category overrides; MetricKit crash capture; and widget UI.
  • Website/PWA: Astro 5 + Tailwind 4 static site with landing, app, app-info, contact, privacy, and terms routes. The /app PWA has a local wallet, guest-token bootstrap, merchant/category recommendation, geolocation-assisted defaults, and category overview.
  • Backend: TypeScript/Express on Node 20, wrapped by serverless-http for Lambda. API Gateway and CloudFront front the API; DynamoDB stores product data; Plaid, Google Places/Knowledge Graph, Bedrock Nova Micro, and SES provide integrations.

Backend and security

  • Protected gateway requests pass through a Lambda request authorizer. Express then applies optional, required, or registered-user checks per route.
  • Supported identities are guest JWT, Google token, Apple token, native/custom JWT, and a non-production dev key. Native auth includes signup, login, email verification, resend, refresh, forgot-password, reset-code verification, and password reset.
  • POST /v1/auth/guest, POST /v1/plaid/webhook, and GET /health have explicit public API Gateway events. The Plaid webhook verifies Plaid-Verification signatures and request-body hashes.
  • Controls include API Gateway throttling (400 requests/s, burst 200), API Lambda reserved concurrency 20, Express burst limits, and a persistent DynamoDB daily quota for guest/unregistered expensive calls.
  • Plaid token writes use AES-256-GCM. The repository can read legacy AES-256-CBC ciphertext to support migration.
  • Registered users can delete their account through DELETE /v1/account; the backend removes account-scoped records and best-effort revokes linked Plaid items, while clients clear local session data after success.

API surface

The live router in raw/croe/src/api/routes.ts is authoritative. It covers health, forms, crash telemetry, brands, recommendations and feedback, cards, user settings/overrides/preferences, guest and registered auth, and Plaid connection/transaction/insights operations. src/api/routeRegistry.ts now covers the live route set and has a unit-test parity check against the Express routers; it remains a hand-maintained contract description rather than generated OpenAPI.

Data model

The backend provisions 13 DynamoDB tables:

  1. MonetUsers
  2. MonetCredentials
  3. MonetOverrides
  4. MonetRecommendationPreferences
  5. MonetRecommendationFeedback
  6. MonetTransactions
  7. MonetInsightsCache
  8. MonetBrandCache
  9. MonetPlaidItemIndex
  10. MonetMerchantEnrichment
  11. MonetCategorizationAudit
  12. MonetRateLimits
  13. MonetFormSubmissions

CloudFormation uses on-demand billing. Durable tables use deletion protection and most use point-in-time recovery; audit and rate-limit tables use TTL where appropriate. Local setup creates the same table set except MonetFormSubmissions, which is currently absent from src/init-db.ts.

Rewards model

The server catalog currently contains 26 supported cards. The shared category taxonomy has 32 raw values including OTHER. Reward structures include flat/category rates, rotating schedules, ranked-spend tiers, caps, custom overrides, and merchant network restrictions. The taxonomy and popular-brand maps remain hand-maintained across repositories.
